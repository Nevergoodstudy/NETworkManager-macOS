## 实现与操作

在「现场项目 → 售后维护 → 授权单服务复测」中，新增「TLS 握手与证书校验」和「HTTP HEAD 响应」。工程师分别选择方法、核对授权引用与时间窗后启动；结果只记录所选层，底层连接成功不自动产生其他层的成功结论。原有系统 DNS、TCP、指定 DNS 和指定 IP TCP 方法继续使用原执行路径。

TLS 使用 Network.framework 的 `NWConnection` 和系统证书链、主机名校验，不覆盖信任结果。成功后保存可观测的对端、TLS 版本和密码套件；证书校验、握手、传输、超时与取消分别记录。HTTP 使用独立 ephemeral URLSession 发送 HEAD，仅 2xx 判为本项成功，其他响应保留实际状态码。HTTP 失败不等于 TLS 失败；HTTPS 的 TLS 指标存在时才记录该事实。

- HTTP 可选 HTTP/HTTPS、端口及以 `/` 开头的路径；切换协议设置默认端口 80/443。修改方法、协议、端口或路径会撤销授权确认。
- 接受 ASCII DNS 主机名和数字 IPv4/IPv6；不接受含用户名、端口或 URL 的主机字段。路径不接受查询、片段、控制字符、反斜线、百分号转义和 `//` 开头，最大 1024 字节。
- 不发送用户凭据和 Cookie，不保留响应头、正文或重定向 Location，不跟随重定向。非服务器信任认证挑战停止检查，不申请凭据。
- 复测总时限 5 秒，取消和到期都会清理连接/会话。底层执行接口允许 0.05–15 秒范围，用例使用较短回环期限。
- 记录传输对端与代理标记。代理地址不作为源服务器地址；未测到源地址或地址族时写「未记录」，不从输入主机猜测。当前仍未测量路由和接口，因此不宣称与交接基线直接可比。

执行结果进入现有 SQLite 诊断历史，支持从历史按原参数重新运行和诊断 JSON 导出。工程师显式附加结果后，项目保存结构化服务证据、方法、端口和 HTTP 参数；首次附加 TLS/HTTP 将项目升级为 schema 5。没有新增服务记录的旧项目保持原版本，读取接受 schema 1–5。旧 DNS/TCP 记录缺少新可选字段仍可解码。

默认项目报告只列关联数量；详细报告包含服务请求和观测。源项目、本地事件库及完整诊断 JSON 是工程资料，仍可能含内部主机、地址和业务路径，不等同于筛选后的分享报告。
