### 已完成的实现

- **DNS 总时限**：解析指定服务器地址、UDP 往返、TCP 连接、发送和逐段读取共享同一个单调时钟 deadline；UDP 截断回退不会重新获得一份超时预算。非有限值、零和负超时会被拒绝。
- **传输边界**：指定服务器只解析一次，TCP 回退复用同一地址；非阻塞套接字检查连接结果并处理临时不可读写。UDP 使用连接后的对端，接收缓冲区为 65,535 字节；TCP 按两字节长度前缀组装完整帧。提前 EOF 与短帧报告报文错误；等待期间可取消，避免 SIGPIPE 终止进程。
- **响应契约**：校验事务 ID、QR/opcode、唯一 question、名称、类型与 IN 类之后才信任 UDP 的 TC 标记。完整响应校验所有声明的 section、记录边界、已支持 IN 类型的 RDATA 和结尾，只返回 answer section 中所选类型的 IN 记录。
- **记录与错误**：支持 A、AAAA、CNAME、NS、PTR、MX、SRV、SOA、TXT、CAA；压缩名称按整条报文的绝对偏移解码，限制指针、标签与名称长度。SOA 保留两个名称和五个数值。非零基础 RCODE（例如 SERVFAIL/NXDOMAIN）变成失败，NOERROR 且没有匹配记录仍是成功。
- **Lookup 状态**：整合已有的初始、加载、错误、成功空结果和表格状态；编辑条件清除旧结果；系统模式只提供 A/AAAA，并解释 TTL 未知。空指定服务器在进入运行状态前校验，避免界面卡住。运行中禁用输入与模式切换，离开页面取消任务。补齐无效 DNS 名称的中文提示。实际观察到的 GUI 状态见下文。

本次没有增加 EDNS 扩展 RCODE 或 DNSSEC 验证。系统解析继续走 macOS DNS-SD，原始记录查询继续要求显式服务器，没有新增隐式公网 DNS 回退。

### T01：CoreWLAN 字段能力评估

已直接阅读 Apple 官方 CoreWLAN API 文档，结论是可继续设计独立的 API 采集器，但当前证据不足以直接替换 mini 采集并宣称权限兼容。

| API / 字段 | 官方说明的无值语义 | 实施约束 |
|---|---|---|
| `CWWiFiClient` / `CWInterface` | 使用 client 提供的接口；直接构造接口涉及低层套接字，默认不适合 sandbox | 使用共享或长期存活的 client，保留接口维度 |
| `ssid()` | 出错、未加入网络或 SSID 无法按支持编码转换时可返回 nil | nil 不能单独归因为权限拒绝或断线 |
| `bssid()`、`wlanChannel()` | 出错或未加入网络时可返回 nil | 保留字段不可用状态，单独取得授权证据 |
| `rssiValue()`、`noiseMeasurement()` | 出错或未加入网络时可返回 0，单位 dBm | 不能把哨兵值显示为确定的有效测量 |
| `transmitRate()` | 出错或未加入网络时可返回 0，单位 Mbps | 缺值、运行错误与有效速率需分别建模 |

这些 API 页面并未完整规定当前各 macOS 版本、签名身份与授权组合的行为。因此仍保留 `system_profiler SPAirPortDataType -detailLevel mini`，保持成功空结果与未知非空输出的区分；没有扩大收集 SSID/BSSID、发起扫描、触发位置授权或更改网络设置。后续需在正式身份、支持系统与实际连接状态矩阵中验证 CoreWLAN 的字段与权限行为。

## CI 兼容性跟进 / CI compatibility follow-up

首次推送 576dba0 的 push CI 在 macOS 15 Intel 的 ARP 实采断言失败；同一提交的 PR Intel 核心检查通过。检查发现解析器要求 MAC 地址恰好包含 12 个十六进制字符，而本机 arp 输出可省略各段前导零（例如 1:0:5e:0:0:fb）。后续修复按六个独立的十六进制字节校验并补零，增加全为非补零记录、已补零格式、非法段长度/数量/分隔符的确定性回归；保留未知输出错误分类，并让实采断言输出状态与计数，避免记录原始网络标识。此修复仍属于现有 T01 切片，验收统计不变；最终远端结果以 PR Checks 为准。

The first push run for 576dba0 failed the live ARP assertion on macOS 15 Intel, while the PR Intel core checks passed for the same commit. Inspection found that the parser required exactly 12 hex digits although local Darwin arp output can omit octet padding (for example 1:0:5e:0:0:fb). The follow-up validates six separate hex octets and normalizes padding, with deterministic fixtures for unpadded-only output, padded forms and malformed lengths/counts/separators. Unknown output remains an error; live assertion diagnostics report only status/classification/counts. This remains part of the existing T01 slice and does not change acceptance counts. Final remote results are tracked in PR Checks.

### Implementation and checks

One monotonic deadline covers nameserver resolution, UDP, TCP connect/send and all frame reads. The resolved endpoint is reused for fallback. Nonblocking sockets check connection completion, retry temporary readiness failures and suppress SIGPIPE; UDP accepts the connected endpoint, and TCP requires a complete length-prefixed frame. EOF/short frames fail as malformed rather than waiting for timeout.

The parser validates the ID, QR/opcode, one echoed question, name/type/IN class before trusting TC. It bounds all declared sections and supported IN RDATA, rejects trailing/truncated data and returns only selected-type IN answers. All ten existing record types are covered, including compressed names and full SOA fields. Basic nonzero RCODEs fail the diagnostic; NOERROR without matching data remains successful. EDNS extended RCODE and DNSSEC validation are outside this change.

Lookup has separate initial, loading, failure, successful-empty and table states. Changed inputs clear stale results; missing explicit-server validation runs before setting the running flag. Inputs are disabled while running; leaving cancels the task. System mode supports A/AAAA, resets unsupported selections and explains unknown TTL. The invalid-name diagnostic now has a verified Chinese translation.

The focused DNS suite, full NMTest, NMCheck, Debug app/bundled NMCP build and MCP integration checks passed on arm64 macOS 27.2.1 (26B131), Swift 6.4.2. After the final one-line translation, the focused suite and staged app were rebuilt and rechecked. The staged ad-hoc signature passed `codesign --verify --deep --strict --verbose=2`; this does not establish Developer ID or notarization acceptance. Checked relative documentation/source links existed, and `git diff --check` passed. Swift 5 language mode and the macOS 14 minimum remain unchanged. Existing CommandLineTools search-path warnings remain non-fatal. The Chinese table above lists local temporary evidence logs, which are not portable repository artifacts.

Fixtures cover IPv4/IPv6 loopback UDP and segmented TCP, one shared deadline, partial-frame EOF, cancellation, server failures and successful empty service results. The deadline test uses a 0.18-second UDP delay, 0.08-second TCP byte delays and a 0.38-second query budget, accepting 0.32–0.65 seconds overall; cancellation during a TCP wait must finish within 0.5 seconds.

The staged app, launched through LaunchServices with isolated support storage, was checked for initial and missing-server states, localhost A/AAAA, unknown TTL, stale-result clearing, mode/type transitions, successful empty results and history status. A system A lookup of numeric IPv6 `::1` showed a successful zero-record result. An explicit-server query for invalid `bad..test` failed before networking and appeared as failed history; the rebuilt UI showed the Chinese error and usable controls. Controlled GUI SERVFAIL, timeout, cancellation and leaving during a query still need separate evidence; transport/service fixtures do not satisfy those GUI gates.

### CoreWLAN assessment and remaining gates

Apple documents client-vended interfaces and recommends a shared or long-lived CWWiFiClient. Direct CWInterface construction uses low-level sockets and is not sandbox-safe by default. SSID can be nil on error, no association or unsupported encoding; BSSID/channel can be nil on error or no association. RSSI/noise and transmit rate can return zero on error or no association (dBm and Mbps respectively). These sentinels alone do not establish permission denial or a disconnected state.

The reviewed API pages do not establish a complete supported-OS and signed-permission matrix. The mini system_profiler collector remains in place, preserving empty versus unrecognized output without guessing the cause. No Wi-Fi scan, SSID/BSSID collection, location-permission grant or network-setting change was performed for this assessment.

The roadmap still has seven implementation slices across T01/T02/T03, covering 3/16 main items with **0/16 fully accepted**. This hardens the existing DNS slice rather than inflating the slice count. T01 still needs controlled inventory UI, supported-OS fields and signed permissions. T02 still needs VPN split DNS, `.local`, IPv6-only networks, multiple interfaces and controlled GUI failure/cancellation. T03 needs wider GUI/MCP runtime adoption and unified budgets. T04 and T05–T14 received no new implementation here; T15/T16 still require real devices/platforms, Developer ID/notarization/Gatekeeper and strict concurrency migration. Loopback IPv6 and ad-hoc signatures do not satisfy those acceptance gates.
